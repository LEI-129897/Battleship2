## 1. Convenção escolhida

Para esta tarefa, foi selecionada a verificação das convenções de nomes de classes e interfaces em Java, utilizando a ferramenta Checkstyle.

A regra escolhida foi `TypeName`, que permite verificar se os identificadores seguem a convenção *UpperCamelCase* (também conhecida como *PascalCase*).

Segundo esta convenção, os nomes devem começar por uma letra maiúscula e cada palavra seguinte deve também começar por maiúscula, sem utilização de espaços ou underscores.

Exemplos de nomes válidos:
- `BattleShip`
- `GameBoard`
- `PlayerManager`

Exemplos de nomes inválidos:
- `battleShip`
- `game_board`
- `player_manager`

O objetivo desta verificação é garantir a consistência dos identificadores utilizados no projeto, melhorando a legibilidade e facilitando a manutenção do código.

## 2. Configuração do Checkstyle

Foi configurado um ficheiro XML com a regra `TypeName`, responsável pela verificação das convenções de nomes de classes e interfaces.

Esta configuração foi integrada num workflow do GitHub Actions, permitindo executar automaticamente a análise do código e verificar o cumprimento das convenções estabelecidas.

O *quality gate* foi definido para falhar quando são identificadas violações da regra, impedindo que código com identificadores incorretos seja aceite sem que o problema seja sinalizado.

## 4. Reflexão

A utilização do Checkstyle permite automatizar a verificação das convenções de nomes de classes e interfaces, contribuindo para manter a consistência e a legibilidade do código. No entanto, a ferramenta apenas verifica se os identificadores cumprem os padrões sintáticos definidos, não conseguindo avaliar se os nomes escolhidos são claros, significativos ou adequados à responsabilidade das classes e interfaces. Assim, embora o Checkstyle seja útil para garantir a uniformidade das convenções de programação, continua a ser necessária uma análise humana para avaliar a qualidade semântica dos identificadores.
